# wake-up-up 機能拡張 仕様書(案)

[requirements.md](requirements.md) と [design.md](design.md) の MVP に対する拡張。
実装できる粒度まで、データ・画面・ロジック・境界条件・テストを定める。

## 0. 全体方針

### 0.1 守る設計原則(MVP から継続)
- 派生できる値(連続日数、最長記録、残高など)は保存せず、記録から計算する。
- ロジックは Flutter に依存しない純粋関数にして単体テストする(`lib/domain/`)。
- 現在時刻は `clockProvider` 経由で取得し、テストで固定する。
- 公開クラス・関数には日本語のドキュメントコメントを書く。
- 「日」は午前3:00 区切り(論理日付)。

### 0.2 実装フェーズ

| フェーズ | 内容 | 規模 | 依存 |
|---|---|---|---|
| 1 | 設定基盤の整理、テーマカラー、ダークモード、ボタンの文言・アイコン | 中 | なし |
| 2 | ベスト記録、連続日数の節目演出(バッジ)、月カレンダー | 中 | なし(フェーズ1と並行可) |
| 3 | ポイントの使い道(ご褒美と交換) | 大 | DB マイグレーション |
| 4 | 目標の段階的な前倒し | 中 | フェーズ1の設定基盤 |

フェーズ1を最初に行う。以降の設定項目が増えるため、先に設定の持ち方を整理しておく。

### 0.3 共通の変更点
1. **設定の一括管理**: 設定項目が増えるため、`AppSettings` を導入する(1.1)。
2. **タブを4つに**: ホーム / 履歴 / ご褒美 / 設定(ご褒美はフェーズ3で追加)。
3. **DB をバージョン2に**: ご褒美と交換履歴のテーブルを追加する(フェーズ3、4.3)。
4. **色のハードコードをやめる**: [history_page.dart](../lib/presentation/history_page.dart) の `Colors.green` / `Colors.redAccent` をテーマ連動の色にする(ダークモード対応のため)。

## 2. テーマカラー変更(フェーズ1)

### 2.1 仕様
- 設定画面に「テーマカラー」を追加する。**プリセット8色**から1つ選ぶ(自由な色選択は対象外)。
- 選ぶとすぐ全画面に反映し(プレビュー不要)、端末に保存する。次回起動時も維持する。

| index | 名前 | シード色 |
|---|---|---|
| 0 | オレンジ(現行) | `0xFFFF9800` |
| 1 | 赤 | `0xFFE53935` |
| 2 | ピンク | `0xFFEC407A` |
| 3 | 紫 | `0xFF7E57C2` |
| 4 | 青 | `0xFF1E88E5` |
| 5 | 青緑 | `0xFF00897B` |
| 6 | 緑 | `0xFF43A047` |
| 7 | 茶 | `0xFF8D6E63` |

### 2.2 UI
- 設定画面の最上部に「外観」セクションを置く。
- 色は円形のチップを横に並べる(`Wrap`)。選択中はチェックアイコンと枠線を付ける。
- 各チップに `Semantics(label: '青', selected: true/false)` を付け、色名を読み上げられるようにする。
- タップ領域は 48dp 以上にする。

### 2.3 実装
- `app.dart` の `MaterialApp` を `ConsumerWidget` にして、`settingsProvider` から `ThemeData` を作る。
  ```
  ThemeData _theme(Color seed, Brightness b) =>
      ThemeData(colorSchemeSeed: seed, brightness: b, useMaterial3: true);
  MaterialApp(theme: _theme(seed, light), darkTheme: _theme(seed, dark), themeMode: ...)
  ```
- 成功/失敗の色は `ThemeExtension`(`StatusColors { success, failure }`)として持つ。
  - 成功: ライト `0xFF2E7D32` / ダーク `0xFF81C784`
  - 失敗: `colorScheme.error`
  - 色だけに頼らず、既存のアイコン(チェック/×)を併用する。

### 2.4 境界条件
- 保存値が範囲外 → オレンジに戻す。
- 起動直後に一瞬デフォルト色が見えないよう、設定は `main()` で読み込んでから `runApp` する(現状の流れを踏襲)。

### 2.5 テスト
- 単体: 設定の保存・読み込み、範囲外の値の補正。
- ウィジェット: 色を選ぶと `Theme.of(context).colorScheme.primary` が変わる。再構築しても維持される。
- アクセシビリティ: **8色 × ライト/ダーク × 主要3画面**で `textContrastGuideline` を満たす。
- ゴールデン: 設定画面(外観セクション)、ダークのホーム。

## 4. ボタンの文言・アイコン(フェーズ1)

- **文言**: 1〜8文字(絵文字・全角は1文字と数える)。前後の空白は取り除く。空・空白のみは初期値「起きた」に戻す。

- 「初期値に戻す」ボタンを置く。

### 4.2 UI
- 文言は `TextField`(`maxLength: 8`、カウンタ表示、`textInputAction: done`)。確定時に保存する。
- アイコンはテーマカラーと同様のチップ。読み上げラベルを付ける(例: 「ロケット」)。

### 4.4 テスト

## 5. ベスト記録(フェーズ2)

### 5.1 仕様
履歴タブの最上部に「ベスト記録」カードを置く。

| 項目 | 定義 |
|---|---|
| 最長連続成功 | 連続して成功した日数の最大値(期間の開始日〜終了日も表示) |
| 最も早い起床 | 起床時刻が最も早い記録。時刻と日付を表示 |
| 通算成功日数 | 成功した日の合計(成功率 = 成功日数 ÷ 記録日数も表示) |

- 記録がないときは「まだ記録がありません」とする。

### 5.2 ロジック(`lib/domain/stats.dart`、純粋関数)
- `longestStreak(records)` → `Streak?`(日数、開始日、終了日)。
  日付が連続し、かつ成功した日だけを連続とみなす(記録のない日で途切れる。現在の連続日数 `currentStreak` と同じ扱い)。
- `earliestWake(records)` → `WakeRecord?`。
  比較は「論理日の 0:00 = 午前3:00 からの経過分」で行う。式: `(hour * 60 + minute - 180) % 1440`。
  これにより 3:00 が最も早く、翌 2:59 が最も遅くなる。同値は日付の古い方を採用する。
- `summary(records)` → 通算成功日数、記録日数、成功率。

### 5.3 境界条件
- 記録が1件のとき(最長連続は成功なら1、失敗なら0)。
- 同じ起床時刻が複数ある。月・年をまたぐ連続。
- 成功率の割り算でゼロ除算にならない。

### 5.4 テスト
- 単体: 上記の境界条件。
- ウィジェット: カードの表示、記録ゼロの表示。

## 6. 連続日数の節目演出・バッジ(フェーズ2)

### 6.1 仕様
- 節目: **3 / 7 / 14 / 30 / 50 / 100 / 200 / 365 日**連続成功。
- 成功の記録で連続日数がちょうど節目になり、かつ**その節目に初めて到達したとき**だけ、お祝いのダイアログを出す。
  - 内容: 大きなアイコン、「7日連続達成！」、一言メッセージ、「閉じる」ボタン。
  - 一度途切れてから再び同じ日数に到達してもダイアログは出さない(バッジは取得済みのまま)。
- バッジは**保存せず、最長連続成功から導出する**(最長連続が節目以上なら取得済み)。
  - 履歴タブのベスト記録カードの下に、取得済み/未取得のバッジを横に並べる(未取得はグレー、節目の日数を表示)。
- ボーナスポイントは付けない(ポイント規則は変えない。要確認事項 #1)。
- その他の小さな通知(スナックバー):
  - 「最も早い起床を更新！」: 記録が2件目以降で、過去のどの記録よりも早く起きたとき。
  - 「最長連続記録を更新！」: 連続日数が過去の最長を超え、かつ過去に記録があるとき。
- 複数該当する場合は、ダイアログ(節目)を優先し、スナックバーは出さない。

### 6.2 ロジック
- `detectAchievements(List<WakeRecord> before, WakeRecord added)` → `Achievements`
  - `newMilestone`: `added` を加えた連続日数が節目と一致し、`longestStreak(before)` がその節目未満のとき。
  - `newEarliest`: `before` が空でなく、`added` が `earliestWake(before)` より早いとき。
  - `newLongest`: 連続日数 > `longestStreak(before)` で、`before` が空でないとき。
- `RecordsNotifier.wake()` の戻り値を `WakeResult { record, achievements }` にする。
  ホーム画面は押下後に結果を受け取ってダイアログ/スナックバーを出す。

### 6.3 UI・実装
- ダイアログは標準の `AlertDialog` に `AnimatedScale` でアイコンを拡大表示する程度にとどめる(外部パッケージは使わない)。
- 失敗した日は演出なし。
- ダイアログ表示中に画面が破棄されても例外にならない(`mounted` を確認)。

### 6.4 境界条件
- 日付をまたぐ(午前3:00 区切り)連続のとき。
- 連続が節目を飛び越えない(1日ずつ増えるため、節目はちょうど通る)。
- ボタン連打: 保存が1回だけなので、ダイアログも1回だけ。

### 6.5 テスト
- 単体: 各節目で `newMilestone` が出る/再到達で出ない/途中で失敗して再到達しても出ない。
- ウィジェット: 7日連続の記録でダイアログが出る、閉じられる、2回目の押下では出ない。

## 7. 月カレンダー(フェーズ2)

### 7.1 仕様
- 履歴タブに表示切替(`SegmentedButton`: **カレンダー / リスト**)を置く。初期はカレンダー。
- 外部パッケージは使わず、`GridView`(7列)で自前実装する。

| 要素 | 内容 |
|---|---|
| ヘッダー | 「2026年11月」と、前月・翌月ボタン |
| 曜日行 | 日曜始まり(日 月 火 水 木 金 土)。土曜は青系、日曜は赤系の文字(テーマに従う) |
| 日付セル | 成功: 成功色の背景 + チェック。失敗: 失敗色の背景 + ×。記録なし: 無地。今日: 枠線。未来: 薄く表示 |
| 月の集計 | 「成功 12日 / 失敗 3日 / 成功率 80%」 |

- 日付セルをタップすると、ボトムシートに起床時刻・目標時刻・獲得ポイントを表示する(記録なしの日は「記録なし」)。
- 月の移動範囲: **最初の記録がある月 〜 今日の月**。範囲外のボタンは無効にする。
- 色だけに頼らず、チェック/×のアイコンも併用する(色覚への配慮)。

### 7.2 ロジック
- `monthGrid(year, month)` → 6週×7日の `DateTime?` の表(月初の曜日に合わせて前後を空にする)。
- 各セルの状態 `DayStatus { success, failure, none, future }` を、記録と今日の論理日付から決める。
- 月の集計は `summaryOfMonth(records, year, month)`。
- 日付は論理日付 (`yyyy-MM-dd`) の文字列で照合する。

### 7.3 境界条件
- 月初が日曜/土曜、28日・29日(閏年)・30日・31日の月。
- 記録が1件もない場合は、カレンダーではなく従来どおり「まだ記録がありません」を表示する(ベスト記録・バッジも同様)。
- 未来の日の文字は、コントラスト基準を保つため、薄い色ではなく補助色(`onSurfaceVariant`)と細い字体で表す。
- 行数は、その月に必要な週の数(4〜6週)にする(空の週は出さない)。
- 日付が替わる(午前3:00)と、今日の枠線が自動で移る(`todayProvider` を使う)。

### 7.4 テスト
- 単体: `monthGrid` の各月(2026年2月、2028年2月、2026年11月、2027年1月など)。
- ウィジェット: セルの色・アイコン、月の移動、範囲の制限、セルをタップしたときのボトムシート。
- ゴールデン: 成功・失敗・未来が混ざった月。

## 8. 目標の段階的な前倒し(フェーズ4)

### 8.1 仕様
「**N日連続で成功したら、目標時刻を M分早める**」を、最終目標まで繰り返す。

| 設定 | 選択肢 | 初期値 |
|---|---|---|
| 自動で目標を早める | オン / オフ | オフ |
| 連続成功日数 N | 3 / 5 / 7 / 10 / 14 | 7 |
| 前倒しの幅 M | 5 / 10 / 15 / 30 分 | 15 |
| 最終目標の時刻 | 時刻ピッカー(4:00 以降) | 6:00 |

- 設定画面の「目標」セクションに置き、オンにしたときだけ詳細項目を表示する。
- 「7日連続で成功すると、目標を15分早めます(7:00 → 6:45 → … → 6:00、全4段階)」のように、設定の説明文を動的に表示する。

### 8.2 判定
- **「N日連続」の数え方**: 現在の目標時刻と**同じ目標時刻で記録された成功**が、日付の連続で N 日続いたとき。
  - 各記録が当時の目標時刻を保存しているため、追加の保存項目は不要(導出可能)。
  - 失敗・記録のない日で途切れる。目標が変わった(自動・手動どちらでも)と数え直しになる。
- 判定のタイミング: 成功の記録を保存した直後(`wake()` 内)。
- 条件を満たしたら、新しい目標 = `max(最終目標, 現在の目標 − M分)` に更新する。
  - 今日の記録は古い目標で確定済み。**新しい目標は明日の記録から**適用される。
  - 更新後はダイアログで「明日から目標が 6:45 になります」と知らせる。
- 新しい目標が最終目標に一致したら、「最終目標 6:00 に到達しました！」のダイアログを出し、**自動前倒しをオフにする**。
- 失敗しても目標は戻さない(厳しすぎるため。拡張の余地として要確認事項 #5)。

### 8.3 ロジック(`lib/domain/auto_advance.dart`)
- `streakAtTarget(records, target)` → 現在の目標と同じ目標で連続成功している日数。
- `nextTarget(current, goal, minutes)` → `max(goal, current − minutes)`。
- `evaluateAutoAdvance(records, settings)` → `AutoAdvanceResult?`(from, to, reachedGoal)。条件を満たさなければ `null`。
- 時刻の比較は「午前3:00 からの経過分」で行う(5.2 と同じ換算)。

### 8.4 入力の検証
- 最終目標は現在の目標より**早い時刻**であること。そうでなければ設定画面でエラー表示し、オンにできない。
- 最終目標の下限は 4:00(午前3:00 が日の境界のため、それより前は意味がない)。
- 手動で目標を変更したとき、最終目標より早くなった場合は、自動前倒しをオフにしてスナックバーで知らせる。

### 8.5 境界条件
- N 日ちょうどで条件を満たす/N−1 日では満たさない。
- 途中で失敗して連続が途切れる。記録のない日がある。
- 前倒し後すぐ、新しい目標での連続日数が 0 から数え直しになる。
- 現在の目標が最終目標と等しい(何もしない)。M が大きく最終目標を飛び越える(最終目標で止まる)。
- 日付をまたいだ連続(月末・年末)。

### 8.6 テスト
- 単体: 上記の境界条件、`nextTarget` の丸め。
- ウィジェット: 7日連続の成功で目標が更新され、ダイアログが出る。最終目標到達でオフになる。
- 統合: 更新された目標が再起動後も維持される。

## 9. ポイントの使い道(ご褒美と交換)(フェーズ3)

### 9.1 仕様
- 貯めたポイントを、自分で登録した「ご褒美」と交換できる。
- **ポイントの扱い**:
  - 累計獲得 = これまでの獲得ポイントの合計(減らない。既存の `totalPoints`)。
  - 使用済み = 交換に使ったポイントの合計。
  - **残高 = 累計獲得 − 使用済み**(常に 0 以上)。
- ホームの「累計ポイント」は「**ポイント残高**」に変更する。累計獲得と使用済みは「ご褒美」タブに表示する。

### 9.2 画面(タブ「ご褒美」、4つ目)
1. **ヘッダー**: 残高(大)、累計獲得、使用済み。
2. **ご褒美リスト**: 名前、必要ポイント、残高に対する進捗バー(残高 ÷ 必要ポイント、100% で上限)、「交換」ボタン(残高が足りないときは無効)。
3. **追加ボタン**(FAB)「ご褒美を追加」。
4. **交換履歴**: 日時、ご褒美名、使ったポイントを新しい順に表示(リストの下、または「交換履歴」画面へ遷移)。
5. **空の状態**: 「ご褒美を登録しよう」の案内と、候補のチップ(例:「好きなお菓子 100pt」「コーヒー 50pt」「映画 500pt」)。チップをタップすると入力済みの追加画面が開く。

### 9.3 操作
- **追加・編集**: ダイアログまたは画面で、名前と必要ポイントを入力する。
  - 名前: 1〜30文字。必要ポイント: 1〜99,999 の整数。有効なご褒美は最大20件。
  - 同名のご褒美は許可する(区別は不要)。
- **削除**: 「アーカイブ」として扱い(一覧から消える)、過去の交換履歴は残す。
- **交換**: 確認ダイアログ「『好きなお菓子』を 100pt で交換しますか？ 残高 250 → 150pt」→「交換する」。
  - 成功したらスナックバー「交換しました」を表示し、残高と履歴を更新する。
  - 交換の**取り消しはできない**(確認ダイアログで防ぐ。要確認事項 #2)。
  - 同じご褒美は何度でも交換できる。

### 9.4 データ(DB バージョン2、`onUpgrade`)

```sql
CREATE TABLE rewards (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  cost INTEGER NOT NULL,
  archived INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);
CREATE TABLE redemptions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  reward_id INTEGER,
  reward_name TEXT NOT NULL,   -- 交換時の名前(後から名前を変えても履歴は変わらない)
  cost INTEGER NOT NULL,       -- 交換時のポイント
  redeemed_at INTEGER NOT NULL
);
```
- 既存の `wake_records` はそのまま(`onUpgrade` で上の2テーブルを追加するだけ)。
- **残高は保存しない**: `SUM(wake_records.points) − SUM(redemptions.cost)` で求める。
- **交換は1つのトランザクション**で行う: トランザクション内で残高を計算し、足りなければ失敗を返し、足りれば `redemptions` に追加する。これで残高がマイナスになる不整合を防ぐ(連打・同時実行も安全)。

### 9.5 リポジトリ(`lib/data/reward_repository.dart`)
- `RewardRepository`(抽象)と `SqliteRewardRepository`。
  - `activeRewards()`、`addReward(name, cost)`、`updateReward(id, name, cost)`、`archiveReward(id)`
  - `redeem(rewardId, now)` → `RedeemResult`(成功 / 残高不足 / ご褒美が存在しない)
  - `redemptions()`、`totalSpent()`、`balance()`
- `RecordRepository` と同じデータベースを共有する(同一トランザクションで両テーブルを扱えるため)。
  `SqliteRecordRepository.open()` を共通の `AppDatabase` に切り出す。

### 9.6 境界条件
- 残高ちょうどの交換(残高 = 必要ポイント)は成功し、残高が 0 になる。
- 1ポイント足りない場合は失敗。
- 交換ボタンの連打で二重に交換されない(確認ダイアログ + トランザクション)。
- ご褒美の必要ポイントを編集しても、過去の交換履歴の値は変わらない。
- アーカイブしたご褒美の履歴は残る。20件を超える追加は拒否する。
- マイグレーション: バージョン1のデータベース(既存の記録あり)を開いても、記録が失われず、新しいテーブルが追加される。

### 9.7 テスト
- 単体: 残高の計算、`redeem` の成功・不足・存在しない。
- 統合(実際の SQLite): バージョン1 → 2 のマイグレーション、交換のトランザクション、再起動後の残高。
- ウィジェット: 進捗バー、交換ボタンの有効/無効、確認ダイアログ、空の状態、入力検証。
- アクセシビリティ: 交換ボタンのラベル(「好きなお菓子を100ポイントで交換」)。
