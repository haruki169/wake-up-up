# wake-up-up 設計書(MVP)

要件は [requirements.md](requirements.md) を参照。

## 1. 画面構成

| 画面 | 内容 |
|---|---|
| ホーム | 今日の状態(未記録/成功/失敗)、目標時刻、「起きた」ボタン、累計ポイント、連続成功日数 |
| 履歴 | 日ごとの起床時刻・目標時刻・成否・獲得ポイントのリスト(新しい順) |
| 設定 | 目標起床時刻の変更 |

ナビゲーションは下部タブ(ホーム/履歴/設定)。

## 2. データモデル

### WakeRecord(1日1件)
| 項目 | 型 | 説明 |
|---|---|---|
| date | String (yyyy-MM-dd) | 午前3:00境界で決めた「論理日付」。主キー |
| wokeAt | DateTime | 「起きた」を押した実時刻 |
| targetTime | String (HH:mm) | 記録時点の目標時刻 |
| success | bool | 成否 |
| points | int | 獲得ポイント(失敗は0) |

### 設定
- targetTime(HH:mm)。初期値 7:00

### 派生値(保存しない)
- 累計ポイント = points の合計
- 連続成功日数 = 直近から遡って success が連続する日数(今日が未記録なら昨日から数える)

## 3. ロジック(純粋関数・単体テスト対象)

- `logicalDate(DateTime now)`: 3:00 より前なら前日の日付を返す
- `judge(wokeAt, targetTime)`: 論理日付の目標時刻と比較して成否を返す
  - 論理日付の目標時刻と比較する。0:00〜2:59 に押した場合は前日扱いで、目標時刻を過ぎているため失敗になる
- `calcPoints(wokeAt, targetTime)`: 失敗は0。成功は 10 + min(5, 目標との差(分) ÷ 10 の切り捨て)

## 4. アーキテクチャ

- Flutter + Dart、状態管理は Riverpod
- 層構成:
  - `domain/`: モデル、判定・ポイント計算(Flutter 非依存)
  - `data/`: リポジトリ(ローカル保存)
  - `presentation/`: 画面、Provider
- 保存: SQLite(sqflite)。WakeRecord を1テーブル、設定は shared_preferences(コード生成が不要な sqflite を採用)
- 時刻の取得は `Clock` を注入し、テストで固定できるようにする

## 5. タスク分解

1. Flutter プロジェクト作成(iOS / Android)、依存追加、フォルダ構成
2. domain: モデルと `logicalDate` / `judge` / `calcPoints` + 単体テスト
3. data: drift テーブル、リポジトリ、設定の保存
4. 設定画面: 目標時刻の変更
5. ホーム画面: 「起きた」ボタン、1日1回の制御、状態・ポイント・連続日数の表示
6. 履歴画面: 一覧表示
7. 結合確認(iOS / Android 実機またはシミュレータ)と調整

順序は 1 → 2 → 3 → (4, 5, 6) → 7。4〜6 は 3 の後なら並行可能。

## 6. 補足・注意点
- 1日1回制約は date を主キーにして DB 側でも担保する。
- 端末の時刻やタイムゾーンを変更された場合の扱いは MVP では考慮しない(自分専用のため)。
- 日付境界の午前3:00は定数として1か所に定義する。
